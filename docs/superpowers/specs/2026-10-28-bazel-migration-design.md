# Bazel Migration Design

**Project:** autopilot-security-sensor (`github.com/invisible-tech/autopilot-security-sensor`)
**Date:** 2026-10-28
**Status:** Approved

---

## Goals

1. **Build speed** — remote caching via Buildbuddy eliminates redundant recompilation in CI and locally.
2. **Reproducibility** — hermetic builds: pinned Go toolchain, pinned base images by digest, no host environment leakage.
3. **Monorepo readiness** — `MODULE.bazel` declares a clean module boundary; the package structure anticipates the cloud-agnostic extension in spec 2.
4. **Container builds** — `rules_oci` replaces manual Dockerfiles; image builds are fully cacheable and daemon-free.

---

## Scope

This is **spec 1 of 2**. It covers the Bazel build system migration only. Spec 2 covers the cloud-agnostic provider abstraction and Grafana/reporting output. The `BUILD` file structure in this spec is deliberately shaped to make spec 2 additive rather than a retrofit.

Out of scope: cloud provider abstraction, Grafana integration, new feature development.

---

## Migration Strategy

**Incremental, two-phase.** Each phase is independently shippable and testable.

- **Phase 1:** Bazel Go builds — `MODULE.bazel`, Gazelle-generated `BUILD.bazel` files, GitHub Actions + Buildbuddy wiring. The existing Makefile Docker targets and Dockerfiles are untouched.
- **Phase 2:** Container builds — `rules_oci` targets replace `build/Dockerfile.*`. Makefile reduced to thin wrappers. Dockerfiles deleted.

Both `go build` and `bazel build` coexist through Phase 1. After Phase 2, `bazel` is the sole build path.


## MODULE.bazel

```python
module(
    name = "autopilot-security-sensor",
    version = "0.1.0",
)

bazel_dep(name = "rules_go", version = "0.46.0")
bazel_dep(name = "gazelle", version = "0.35.0")
bazel_dep(name = "rules_oci", version = "1.7.4")
bazel_dep(name = "container_structure_test", version = "1.16.0")
bazel_dep(name = "rules_pkg", version = "0.10.1")

# Pinned Go toolchain
go_sdk = use_extension("@rules_go//go:extensions.bzl", "go_sdk")
go_sdk.download(version = "1.22.0")

# External Go deps from go.mod (Gazelle-managed)
go_deps = use_extension("@gazelle//:extensions.bzl", "go_deps")
go_deps.from_file(go_mod = "//:go.mod")
use_repo(go_deps,
    "com_github_sirupsen_logrus",
    "com_github_prometheus_client_golang",
    "io_k8s_api",
    "io_k8s_apimachinery",
    # ... full list generated by: bazel run //:gazelle-update-repos
)

# Added at start of Phase 2: base image pinned by digest (not tag)
# Digest resolved at migration time via: crane digest gcr.io/distroless/static-debian12:nonroot
oci = use_extension("@rules_oci//oci:extensions.bzl", "oci")
oci.pull(
    name = "distroless_nonroot",
    digest = "sha256:<resolved-during-phase-2>",
    image = "gcr.io/distroless/static-debian12",
)
use_repo(oci, "distroless_nonroot")
```

`go.mod` and `go.sum` remain authoritative for `go build`. Gazelle reads them — adding a dependency is still `go get`, then `bazel run //:gazelle-update-repos`.

## Root BUILD.bazel

```python
load("@bazel_gazelle//:def.bzl", "gazelle")

# gazelle:prefix github.com/invisible-tech/autopilot-security-sensor
package(default_visibility = ["//visibility:private"])

gazelle(name = "gazelle")
```

The `# gazelle:prefix` directive tells Gazelle the Go module path so it generates correct import paths in all `BUILD.bazel` files.

With Bzlmod, `go_deps.from_file` reads `go.mod` directly — there is no `update-repos` target. After `go get <pkg>`, run `bazel run //:gazelle` to update `BUILD.bazel` files, then `bazel mod tidy` to update `MODULE.bazel.lock` and the `use_repo` list.

## .bazelrc

```
common --enable_bzlmod

build --incompatible_strict_action_env
build --sandbox_default_allow_network=false
build --jobs=AUTO

# Race detector on for tests, off for binaries
build --@rules_go//go/config:race=false
test  --@rules_go//go/config:race=true

# Buildbuddy remote cache
build:remote-cache --remote_cache=grpcs://remote.buildbuddy.io
build:remote-cache --remote_header=x-buildbuddy-api-key=${BUILDBUDDY_API_KEY}
build:remote-cache --remote_upload_local_results=true

# CI profile (--config=ci set in GitHub Actions)
build:ci --config=remote-cache
build:ci --noshow_progress
build:ci --show_result=20
```

Developers run `bazel build //...` without `--config=ci`; local builds read from the remote cache but do not upload by default.

## GitHub Actions

`.github/workflows/build.yml` replaces the existing `go build` / `go test` steps:

```yaml
- name: Build
  run: bazel build --config=ci //...
  env:
    BUILDBUDDY_API_KEY: ${{ secrets.BUILDBUDDY_API_KEY }}

- name: Test
  run: bazel test --config=ci //...
  env:
    BUILDBUDDY_API_KEY: ${{ secrets.BUILDBUDDY_API_KEY }}
```

`BUILDBUDDY_API_KEY` is stored as a GitHub Actions secret. It is never committed to the repository.

## Phase 2: Container Builds with rules_oci

Each binary follows the same pattern. Shown for `agent`:

```python
# cmd/agent/BUILD.bazel (additions to Gazelle-generated file)
load("@rules_oci//oci:defs.bzl", "oci_image", "oci_push", "oci_tarball")
load("@rules_pkg//pkg:tar.bzl", "pkg_tar")

pkg_tar(
    name = "agent_layer",
    srcs = [":agent"],
)

oci_image(
    name = "agent_image",
    base = "@distroless_nonroot",
    tars = [":agent_layer"],
    entrypoint = ["/agent"],
)

oci_push(
    name = "agent_push",
    image = ":agent_image",
    repository = "gcr.io/invisible-sre-sandbox/apss-agent",
    # Override at CLI for cloud-agnostic targeting:
    # bazel run //cmd/agent:agent_push --@rules_oci//oci:default_repository=<ecr-or-acr-url>
)
```

`oci_push`'s `repository` attribute is overridable at the command line, which is the hook spec 2 uses for cloud-agnostic registry targeting.

### Makefile (thin wrappers after Phase 2)

```makefile
build:
	bazel build //cmd/...

test:
	bazel test //...

test-coverage:
	bazel coverage //... --combined_report=lcov

docker-build:
	bazel build //cmd/agent:agent_image //cmd/controller:controller_image //cmd/webhook:webhook_image

docker-push:
	bazel run //cmd/agent:agent_push
	bazel run //cmd/controller:controller_push
	bazel run //cmd/webhook:webhook_push

clean:
	bazel clean
```

## Visibility Policy

`default_visibility = ["//visibility:private"]` is set at the root. Individual targets that form genuine shared interfaces declare `visibility = ["//visibility:public"]`. This prevents cloud-specific implementations (added in spec 2) from being imported directly instead of through their interface.

## Developer Workflow Summary

| Task | Command |
|---|---|
| Build all binaries | `bazel build //cmd/...` |
| Run all tests | `bazel test //...` |
| Update BUILD files after go.mod change | `bazel run //:gazelle` |
| Sync go.mod dep graph into MODULE.bazel.lock | `bazel mod tidy` |
| Build container images | `bazel build //cmd/agent:agent_image ...` |
| Push container images | `bazel run //cmd/agent:agent_push` |
| Push to alternate registry | `bazel run //cmd/agent:agent_push -- --repository=<url>` |
