# Cloud-Agnostic Architecture and Grafana Reporting Design

**Project:** autopilot-security-sensor (`github.com/invisible-tech/autopilot-security-sensor`)
**Date:** 2026-10-28
**Status:** Approved
**Spec:** 2 of 2 (follows `2026-10-28-bazel-migration-design.md`)

---

## Goals

1. **Cloud-agnostic operation** — remove hardcoded GCP defaults; the sensor runs identically on GKE, EKS, AKS, or any conformant Kubernetes cluster.
2. **Pluggable alert sinks** — introduce an `AlertBus` with fan-out dispatch and optional per-sink routing, replacing the direct Sweet Security coupling in the controller.
3. **Grafana reporting** — push-based alert annotations (Grafana annotations API) and pull-based dashboard (enriched Prometheus metrics + provisioned ConfigMap).
4. **Kubernetes-native audit log ingestion** — replace the GCP Pub/Sub audit log processor with a standard Kubernetes audit webhook receiver.

---

## Scope

This spec covers architecture and feature changes only. Build system changes are in spec 1 (`2026-10-28-bazel-migration-design.md`). This spec assumes spec 1 is complete and Bazel `BUILD.bazel` files will be generated by Gazelle for all new packages.

Out of scope: per-cloud metadata enrichment beyond `ClusterConfig`, alert deduplication, alert persistence beyond current in-memory store, remote execution in CI.

---

## Context: What Was Already Cloud-Agnostic

The sensor logic (`pkg/procmon`, `pkg/netpolicy`, `pkg/fileintegrity`, `pkg/monitor`) has zero GCP SDK imports. The controller and webhook use only standard Kubernetes API client packages. The `/metrics` endpoint and Prometheus `ServiceMonitor` already exist.

The GCP coupling is limited to:
1. Hardcoded `gcr.io/invisible-sre-sandbox/...` image defaults in `config.go` and Helm values
2. `auditLogProcessor.source: pubsub` in Helm — Pub/Sub is GCP-only
3. `gke-managed-system` namespace exclusion hardcoded in Helm defaults
4. GKE cluster names hardcoded in deploy scripts

## Core Abstractions

### `pkg/reporting/sink/sink.go`

```go
package sink

import (
    "context"
    "github.com/invisible-tech/autopilot-security-sensor/internal/types"
)

// AlertSink receives security alerts for processing or forwarding.
type AlertSink interface {
    Name() string
    Send(ctx context.Context, alert *types.Alert) error
}

// Filter is a predicate on an alert. Return true to allow, false to skip.
// A nil Filter means accept all (fan-out behavior).
type Filter func(alert *types.Alert) bool

// Registration pairs a sink with its optional filter.
// Per-sink timeouts are not supported in this spec — the bus default applies to all sinks.
type Registration struct {
    Sink   AlertSink
    Filter Filter    // nil = accept all
}
```

### `pkg/reporting/bus/bus.go`

```go
type Bus struct {
    mu      sync.RWMutex
    sinks   []sink.Registration
    timeout time.Duration // default per-sink timeout
    log     *logrus.Logger
}

func New(defaultTimeout time.Duration, log *logrus.Logger) *Bus

// Register adds a sink. Filter may be nil for fan-out behavior.
func (b *Bus) Register(s sink.AlertSink, f sink.Filter)

// Publish fans out to all sinks concurrently.
// Each sink runs with its own timeout context.
// Errors are logged but never block other sinks.
// Returns combined error only if ALL sinks fail.
func (b *Bus) Publish(ctx context.Context, alert *types.Alert) error
```

**Fan-out → routing evolution:**

```go
// Fan-out (initial implementation — nil filter):
bus.Register(grafanaSink, nil)
bus.Register(sweetSecuritySink, nil)

// Routed (added later, no refactoring needed):
bus.Register(pagerDutySink, func(a *types.Alert) bool {
    return a.Severity == "CRITICAL"
})
```

**Operational properties of `Publish`:**
- Each sink goroutine gets `min(registration.Timeout, bus.timeout)` — prevents one slow sink from cascading
- Sink errors increment `apss_sink_errors_total{sink=<name>}` before logging
- `Publish` is non-blocking from the caller's perspective: it launches goroutines and returns after all complete (bounded by per-sink timeout), but never waits longer than the longest-running sink's timeout

## Grafana Integration

### Push-based: `pkg/reporting/grafana/annotations.go`

```go
type AnnotationSink struct {
    endpoint string   // http://grafana.monitoring.svc:3000
    apiKey   string
    client   *http.Client
    log      *logrus.Logger
}

func (s *AnnotationSink) Name() string { return "grafana-annotations" }

func (s *AnnotationSink) Send(ctx context.Context, alert *types.Alert) error {
    payload := grafanaAnnotation{
        Time:    alert.Timestamp.UnixMilli(),
        Text:    fmt.Sprintf("[%s] %s — %s/%s", alert.Severity, alert.Description, alert.PodNS, alert.PodName),
        Tags:    []string{"apss", alert.Severity, alert.RuleID, alert.MitreTactic},
        IsRegion: false,
    }
    // POST /api/annotations with Bearer auth
}

type grafanaAnnotation struct {
    Time     int64    `json:"time"`
    Text     string   `json:"text"`
    Tags     []string `json:"tags"`
    IsRegion bool     `json:"isRegion"`
}
```

### Pull-based: `pkg/reporting/grafana/metrics.go`

Registers additional Prometheus metrics alongside the three existing ones in `internal/controller`.

```go
// Existing (unchanged, owned by internal/controller):
//   apss_events_received_total{type, severity, namespace}
//   apss_alerts_generated_total{rule, severity}
//   apss_active_agents

// New (registered by pkg/reporting/grafana):
apss_alerts_by_mitre_total{tactic, technique_id, severity}
apss_alert_severity_gauge{severity}            // current open alert count by severity
apss_events_by_namespace_total{namespace, type}
apss_sink_send_duration_seconds{sink}          // histogram — sink latency
apss_sink_errors_total{sink}                   // counter — sink failure rate
```

`apss_sink_send_duration_seconds` and `apss_sink_errors_total` make the bus itself observable — Grafana can alert on sink degradation independently of alert volume.

### Dashboard ConfigMap: `deploy/helm/templates/grafana-dashboard.yaml`

A Kubernetes `ConfigMap` with label `grafana_dashboard: "1"`, picked up automatically by Grafana's sidecar dashboard provisioner. Enabled via `grafana.dashboardProvisioning: true` in Helm values (off by default).

Dashboard panels:
- Alert rate by severity (time series)
- Events by namespace (heatmap)
- MITRE tactic distribution (bar chart)
- Active agents (stat panel)
- Sink health: error rate + latency per sink (time series)
- Alert timeline with annotations overlay

## Kubernetes Audit Webhook

### `internal/audit/handler.go`

```go
// Handler receives Kubernetes audit EventList batches and converts
// filtered events into SecurityEvents for the controller.
type Handler struct {
    ingestFn func(context.Context, *types.SecurityEvent) error
    log      *logrus.Logger
}

func New(ingestFn func(context.Context, *types.SecurityEvent) error, log *logrus.Logger) *Handler
func (h *Handler) Handle(w http.ResponseWriter, r *http.Request)
```

**Processing contract:**
1. Decode `audit.k8s.io/v1.EventList` from request body
2. Respond HTTP 200 immediately (before processing) — prevents API server queue backup
3. Range over `items[]`, filter to sensitive resources only (see below)
4. Convert each matching item to `types.SecurityEvent{Type: "k8s_audit"}` and call `ingestFn`

**Filtered resources:**

| Resource | Verbs | Reason |
|---|---|---|
| `secrets` | create, update, patch, delete | Credential access |
| `clusterrolebindings`, `rolebindings` | create, delete | Privilege escalation |
| `pods/exec` | create | Interactive shell access |
| `pods/portforward` | create | Lateral movement |
| `serviceaccounts` | create | Token minting |

All other audit events are discarded on the handler — not enqueued.

**New server route** in `internal/server/server.go`:
```go
mux.HandleFunc("/audit/webhook", auditHandler.Handle)
```

### Cluster-side audit policy (documented, not automated)

```yaml
# audit-policy.yaml — identical syntax on GKE, EKS, AKS, kubeadm
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  - level: RequestResponse
    resources:
      - group: ""
        resources: ["secrets", "serviceaccounts"]
      - group: "rbac.authorization.k8s.io"
        resources: ["clusterrolebindings", "rolebindings"]
    verbs: ["create", "update", "patch", "delete"]
  - level: Request
    resources:
      - group: ""
        resources: ["pods/exec", "pods/portforward"]
    verbs: ["create"]
  - level: None
```

Per-provider configuration instructions (where to set `--audit-webhook-config-file`) are documented in `docs/audit-webhook-setup.md`, one section per provider.

## Cloud-Agnostic Config Changes

### `internal/config/config.go`

```go
// Remove hardcoded gcr.io default:
// Before: SidecarImage: GetEnv("SIDECAR_IMAGE", "gcr.io/invisible-sre-sandbox/apss-agent:latest")
// After:
SidecarImage: GetEnv("SIDECAR_IMAGE", ""),  // required — no default

// New types:

type GrafanaConfig struct {
    Enabled            bool
    Endpoint           string
    APIKey             string
    AnnotationsEnabled bool
    SinkTimeout        time.Duration
}

type ClusterConfig struct {
    Name     string // CLUSTER_NAME env var
    Provider string // CLUSTER_PROVIDER: gcp | aws | azure | generic
    Region   string // CLUSTER_REGION env var
}

func DefaultGrafanaConfig() GrafanaConfig {
    return GrafanaConfig{
        Enabled:            os.Getenv("GRAFANA_ENDPOINT") != "",
        Endpoint:           GetEnv("GRAFANA_ENDPOINT", ""),
        APIKey:             GetEnv("GRAFANA_API_KEY", ""),
        AnnotationsEnabled: GetEnv("GRAFANA_ANNOTATIONS_ENABLED", "true") == "true",
        SinkTimeout:        GetEnvDuration("GRAFANA_SINK_TIMEOUT", 10*time.Second),
    }
}

func DefaultClusterConfig() ClusterConfig {
    return ClusterConfig{
        Name:     GetEnv("CLUSTER_NAME", "unknown"),
        Provider: GetEnv("CLUSTER_PROVIDER", "generic"),
        Region:   GetEnv("CLUSTER_REGION", ""),
    }
}
```

`ClusterConfig` values are injected into every `types.Alert.Metadata` by the controller, so all sinks (Sweet Security, Grafana) receive cluster identity without cloud-specific code.

## `cmd/controller/main.go` — Wiring

The main entry point is where all sink registrations happen. The controller itself has no knowledge of which sinks exist.

```go
func main() {
    log := logrus.New()
    cfg := config.DefaultControllerConfig()
    grafanaCfg := config.DefaultGrafanaConfig()
    clusterCfg := config.DefaultClusterConfig()

    ctrl := controller.New(cfg, log)

    alertBus := bus.New(10*time.Second, log)

    // Always register Sweet Security if configured
    if cfg.SweetSecurityEnabled {
        alertBus.Register(sweetsecurity.NewSink(cfg, log), nil)
    }

    // Register Grafana annotation sink if configured
    if grafanaCfg.Enabled && grafanaCfg.AnnotationsEnabled {
        alertBus.Register(grafana.NewAnnotationSink(grafanaCfg, log), nil)
    }

    // Register enriched metrics (always — no sink, just metric registration)
    grafana.RegisterMetrics()

    ctrl.SetAlertBus(alertBus)
    ctrl.SetClusterConfig(clusterCfg)

    // ... server setup, audit handler wiring, start
}
```

## What This Spec Does Not Cover

- Per-cloud metadata enrichment (e.g. AWS instance tags, GCP project labels)
- Alert deduplication or suppression windows
- Alert persistence beyond the current in-memory ring buffer
- Grafana alerting rules (separate from dashboard provisioning)
- Additional sink implementations beyond Sweet Security and Grafana (Slack, PagerDuty) — those register against the existing `AlertSink` interface with no further architectural change
