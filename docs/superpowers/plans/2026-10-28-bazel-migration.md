# Bazel Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the autopilot-security-sensor build system from `make` + `go build` to Bazel with Bzlmod, Gazelle-managed BUILD files, Buildbuddy remote caching, GitHub Actions CI, and `rules_oci` container image builds replacing the three Dockerfiles.

**Architecture:** Two-phase migration. Phase 1 adds Bazel scaffolding alongside the existing Makefile/Docker toolchain, verifies Go builds and tests pass under Bazel, then wires in CI + Buildbuddy. Phase 2 adds `rules_oci` container targets, updates the Makefile to thin wrappers, and deletes the Dockerfiles. Both toolchains coexist until Phase 2 is complete.

**Tech Stack:** Bazel 7.4.1 (via Bazelisk), rules_go 0.46.0, Gazelle 0.35.0, rules_oci 1.7.4, rules_pkg 0.10.1, Buildbuddy free tier, GitHub Actions.

## Global Constraints

- Bazel version: `7.4.1` (pinned in `.bazelversion`)
- Go module path: `github.com/invisible-tech/autopilot-security-sensor`
- Go version: `1.22.0` (pinned in `go_sdk.download`)
- Registry: `gcr.io/invisible-sre-sandbox`
- All existing `go test ./...` tests must pass under `bazel test //...`
- No `go build` calls are deleted until Phase 2 is complete
- `BUILDBUDDY_API_KEY` is stored as a GitHub Actions secret — never committed

```python

    name = "autopilot-security-sensor",
    version = "0.1.0",
)

- [ ] **Step 5: Create `.bazelrc`**

build --sandbox_default_allow_network=false
build --jobs=AUTO

build --@rules_go//go/config:race=false
test  --@rules_go//go/config:race=true

build:remote-cache --remote_header=x-buildbuddy-api-key=${BUILDBUDDY_API_KEY}
build:remote-cache --remote_upload_local_results=true

build:ci --config=remote-cache
build:ci --noshow_progress
build:ci --show_result=20
```

### Task 3: GitHub Actions + Buildbuddy CI integration

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `.bazelrc` CI profile from Task 1
- Produces: CI pipeline that builds and tests on every push/PR using Buildbuddy remote cache

- [ ] **Step 1: Add Buildbuddy API key as GitHub Actions secret**

1. Go to [app.buildbuddy.io](https://app.buildbuddy.io) and create a free account.
2. Create a new org → go to Settings → API Keys → copy the API key.
3. In your GitHub repo: Settings → Secrets and variables → Actions → New repository secret.
4. Name: `BUILDBUDDY_API_KEY`, Value: the API key you copied.

- [ ] **Step 2: Create `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Mount Bazel cache
        uses: actions/cache@v4
        with:
          path: |
            ~/.cache/bazel
          key: bazel-${{ runner.os }}-${{ hashFiles('MODULE.bazel.lock') }}
          restore-keys: |
            bazel-${{ runner.os }}-

      - name: Build
        run: bazel build --config=ci //cmd/agent //cmd/controller //cmd/webhook
        env:
          BUILDBUDDY_API_KEY: ${{ secrets.BUILDBUDDY_API_KEY }}

      - name: Test
        run: bazel test --config=ci //...
        env:
          BUILDBUDDY_API_KEY: ${{ secrets.BUILDBUDDY_API_KEY }}
```

- [ ] **Step 3: Verify the workflow file is valid YAML**

```bash
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo "valid"
```

Expected: `valid`

- [ ] **Step 4: Test CI profile locally (optional but recommended)**

```bash
BUILDBUDDY_API_KEY=your-key-here bazel build --config=ci //cmd/agent
```

Expected: Build succeeds and you see a build event URL in the output like `https://app.buildbuddy.io/invocation/...`. Check Buildbuddy UI to confirm cache hit metrics.

- [ ] **Step 5: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions build and test with Buildbuddy remote cache"
```

- [ ] **Step 2: Overwrite `Makefile` with thin wrappers**

```makefile
# Autopilot Security Sensor — Bazel build wrapper
VERSION ?= 0.1.0

.PHONY: all build test test-coverage docker-build docker-push clean lint fmt help

all: build

build:
	bazel build //cmd/agent //cmd/controller //cmd/webhook

test:
	bazel test //...

test-coverage:
	bazel coverage //... --combined_report=lcov

docker-build:
	bazel build //cmd/agent:agent_image //cmd/controller:controller_image //cmd/webhook:webhook_image

docker-push:
	bazel run //cmd/agent:agent_push
	bazel run //cmd/controller:controller_push
	bazel run //cmd/webhook:webhook_push

clean:
	bazel clean

lint:
	golangci-lint run ./...

fmt:
	go fmt ./...
	goimports -w .

help:
	@echo "APSS - Autopilot Security Sensor"
	@echo ""
	@echo "Targets:"
	@echo "  build         - Build all binaries via Bazel"
	@echo "  test          - Run all tests via Bazel"
	@echo "  test-coverage - Run tests with LCOV coverage report"
	@echo "  docker-build  - Build OCI images via Bazel"
	@echo "  docker-push   - Push OCI images to registry via Bazel"
	@echo "  clean         - Clean Bazel output"
```
